# 回転して保存 → 元の向きに戻して保存 したファイルと、元のファイルの差

## 方法
- 元のファイル: `tmp/jpg.jpg`(iPhone 11 Pro の写真)、`tmp/png.png`(iPhone のスクリーンショット)。
- 一時フォルダにコピーして、コピーを右に r° 回して保存(`r90` など)→ 左に r° 回して保存(`back90` など)した。r = 90, 180, 270。
- `cmp`(バイト単位で比べるコマンド)で、元のファイルと `back*` を比べた。
- 中身の比べ方:
  - 画素: Pillow(libjpeg)で読んで、画素の値(0〜255)の差の絶対値を比べた。
  - 付属情報: JPEG の APP 部分、PNG のチャンクを取り出して比べた。

## cmp の結果

| 比べたファイル | 大きさ(バイト) | cmp の出力 | 違うバイトの数(短い方の長さの中で) |
|---|---|---|---|
| jpg.jpg と back90.jpg | 2,185,070 → 2,183,070 | `differ: byte 56, line 1` | 2,163,580 |
| jpg.jpg と back180.jpg | 2,185,070 → 2,183,070 | `differ: byte 56, line 1` | 2,163,580 |
| jpg.jpg と back270.jpg | 2,185,070 → 2,183,070 | `differ: byte 56, line 1` | 2,163,580 |

## 差の中身

### JPEG(jpg.jpg と back90.jpg / back180.jpg / back270.jpg)

| 場所 | 元 | back* | 理由 |
|---|---|---|---|
| EXIF の向きの値 | 6(右に 90° 回して表示) | 1(回さない) | 画素を表示の向きに並べ直したので、6 のままだと EXIF に従うアプリが二重に回すため |
| EXIF の PixelXDimension × PixelYDimension(単位: 画素) | 4032 × 3024 | 3024 × 4032 | 画像の幅と高さが入れ替わったため |
| 量子化表・ハフマン表の区切り | 量子化表 2 つを 1 つの区切り、ハフマン表 4 つを 1 つの区切りに入れる | 表ごとに別の区切り(量子化表 2 つ、ハフマン表 4 つ) | WIC の書き出し部品の書き方 |
| 圧縮データ(SOS から EOI まで) | 2,174,344 バイト | 2,172,334 バイト | 元は画素をセンサーの向きで保存している。back* は表示の向きで保存している。ブロックの順番と各ブロックの中の値の並びが違うので、符号の並びと長さが違う |

- `cmp` の最初の違い(56 バイト目)は、EXIF の IFD0 の 3 つ目の項目(タグ 0x0112 = 向き)の値の場所。元は 6、back* は 1。
- 読み込んだ画素の差(元を読んで表示の向きに回した絵 と back90.jpg を読んだ絵):

| 色 | 差がある画素の数(全 12,192,768 画素中) | 差の最大(画素の値 0〜255) |
|---|---|---|
| Y(明るさ) | 277,738 | 1 |
| Cb(青の色差) | 49,377 | 1 |
| Cr(赤の色差) | 62,105 | 1 |
| RGB にしたとき | — | 3(平均 0.029) |

- 画素の差の理由: 保存したデータではなく、読み込むときの計算の丸めによる。
  - Y: IDCT(周波数の値から画素に戻す計算)は、縦方向の計算 → 丸め → 横方向の計算 の 2 段で行う。back* は元と比べてデータが 90° 回っているので、縦と横の役割が入れ替わり、途中の丸めのかかり方が変わる。
  - Cb・Cr: IDCT の丸めに加えて、縦横半分に間引いて保存した色を元の大きさに戻す補間でも丸めが入る。libjpeg の補間は、偶数番目と奇数番目の画素で丸めのために足す値が違う(画素の値の 1/16 単位で 8 と 7)。回すと偶数・奇数の位置が入れ替わる。

### PNG(png.png と back90.png / back180.png / back270.png)

| 場所 | 元 | back* | 理由 |
|---|---|---|---|
| 圧縮データ(IDAT の合計) | 128,821 バイト(8 個の IDAT) | 103,788 バイト(2 個の IDAT) | WPF の書き出し部品で圧縮し直すため。行ごとの予測のしかたと圧縮の設定が違う。PNG の圧縮(DEFLATE)は可逆 |
| gAMA チャンク | なし | あり(値 45455 = ガンマ値 0.45455) | WPF の PNG 書き出し部品が足すため |
| チャンクの並び | IHDR, sRGB, eXIf, pHYs, iTXt, IDAT… | IHDR, sRGB, gAMA, pHYs, eXIf, iTXt, IDAT… | WPF の書き出し部品の書く順番 |
| iTXt(XMP) | 元の書き方 | 書き方が違う | WPF の付属情報の書き出し部品が XMP を書き直すため |

- `cmp` の最初の違い(50 バイト目)は、3 つ目のチャンク(47 バイト目から)の長さの欄の最後のバイト。元は eXIf チャンクの長さ 250、back* は gAMA チャンクの長さ 4。
